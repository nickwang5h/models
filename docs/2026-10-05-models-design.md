## 目标

查理·芒格说，至少要掌握约 100 个来自不同学科的模型，才能形成“格栅”。这个站提供 130 张模型卡，每张都深入浅出：开场一读就懂，机制经得起懂行的人挑剔。每张卡后面有情境选择题，帮读者在真实处境里认出该用哪个模型、会错在哪。

成功的标准：

- 读完一张卡，能用自己的话复述这个模型；
- 遇到书里没写的处境，能认出这个模型在起作用；
- 知道它在什么时候不适用。

## 读者

聪明的成年中文读者，大学学过计算机和金融，想建立跨学科的思维格栅。写作遵守 knowledge-compiler 的 `style.md`。

## 内容

### 清单

`knowledge-compiler/maps/models/catalog.json` 收 130 个模型，分 12 类：

| 类别 | 数量 |
|---|---|
| 思维方法 | 12 |
| 数学与统计 | 12 |
| 物理、化学与工程 | 11 |
| 生物与演化 | 10 |
| 系统 | 8 |
| 经济学 | 17 |
| 博弈论 | 7 |
| 心理学与误判 | 20 |
| 商业与战略 | 10 |
| 投资与风险 | 8 |
| 社会、历史与组织 | 8 |
| 计算机与信息 | 7 |

每个模型有 `id`、`name`、`en`、`discipline` 和 `hint`。`hint` 划定范围，避免相邻的模型写重，比如“激励”和“激励偏差”。

### 卡片字段

| 字段 | 内容 |
|---|---|
| `one_line` | 一句话说清，20–40 字 |
| `scene` | 开场故事，120–250 字，真实事件优先，先不点名模型 |
| `mechanism` | Markdown，300–600 字：为什么成立；有公式或数字推演就给出，并用白话再说一遍 |
| `origin` | 出处，60–150 字：学科、提出者、年代、经典证据 |
| `examples` | 恰好 3 个，来自 3 个不同领域，每个是 `{field, title, text}`，`text` 80–160 字 |
| `use` | 3–5 个遇事时问自己的问题 |
| `limits` | 边界与误用，100–250 字 |
| `related` | 3–5 个，每个是 `{id, relation, why}`。`relation` 取 互补、相反、常一起出现、是它的特例、是它的一般化 之一，`id` 必须在清单里 |
| `questions` | 3 道情境单选题，每道 4 个选项、恰好 1 个正确；每个选项带 `feedback`，另有 `explain`。题面不出现模型名 |

卡里不放名人引语，因为最容易出现编造的引语。

### 生成与核对

在 knowledge-compiler 里新增 `study.py models`，分几个阶段：

1. **`cards`**：按清单生成卡片。确定性检查包括字段、字数、`related` 的 id 和 `style.problems`；不合格就把问题发回重写。
2. **`audit`**：另起一次调用，盲审卡片里的事实、出处、年份和人名，列出错误或可疑的说法。有问题就带着这份清单修一次；修后仍有问题，这张卡标为失败，不发布。
3. **`questions`**：根据卡片出题，再由另一次调用盲答。与标准答案不同的题带着理由修一次，修后仍不一致就丢掉。一张卡至少要保留 2 道题。
4. **`export --to <models 仓库>/content`**：每张卡一个 JSON，外加 `index.json`，内容是类别、顺序和标题。

状态和缓存放在 `~/KnowledgeCompiler/study/models/`。测试只用临时目录。

## 站点

- **仓库与部署**：仓库 `~/Projects/models`，纯静态站。构建脚本 `build.mjs` 读 `content/`，在 `dist/` 生成：
  - `index.html`：12 类网格，每类显示卡数，以及已读数和答对数（由页面脚本从本地进度算出）；
  - `d/<类别>.html`：分类页，列出卡片的一句话；
  - `m/<id>.html`：卡片页，包括正文、题目、相关模型（显示关系和理由）以及上一张、下一张；
  - `review.html`：复习，只抽已读卡片的题，答错过的排在前面；
  - 「随机一张」，由脚本跳转到一张未读的卡。
- **交互**：页面不开 JS 也能读，JS 只负责答题、记录进度和复习。进度存在 localStorage，键名为 `models-progress-v1`，内容是 `{read: {id: 日期}, answers: [{q, ok, at}]}`。读写都包在 try/catch 里，读不到就当作没有进度。
- **样式**：手机优先，支持浅色和深色。公式用 KaTeX，从 CDN 加载；只在含 `$` 的页面引入。
- **部署**：Cloudflare Pages 项目 `models`，用 `wrangler pages deploy dist` 部署，绑定自定义域名 models.wuhua.app（可能需要站长在后台操作）。不碰其他 wuhua 站点。

## 验证

- knowledge-compiler 的单元测试覆盖卡片检查、导出和题目处理。
- 站点构建时检查：
  - 每张卡字段齐全；
  - `related` 都指向存在的卡；
  - 每道题恰好一个正确选项；
  - 130 张卡都有页面。
- 站点脚本的进度逻辑有单元测试（node:test）。
- 上线后在线抽查几张卡的页面和题目。
